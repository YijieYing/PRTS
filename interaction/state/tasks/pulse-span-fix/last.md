## 根因与改动

- `pulse/lib/sources.py:165` 的 Codex activity.start/end 来自窗口内全部 agent 事件的 min/max，仅适合归属匹配。原 `pulse/lib/pulse.py:165–167` 将它原样复制为用户段边界，原 202 行只扩张、不收缩边界；原 render 414 行按外包跨度选择「同时」，导致一分钟活动吸收全天其他段。
- 现在 `pulse/lib/pulse.py:160` 的 activity_intervals、166 行 activity_bounds 统一使用 intervals 与 held 证据；computer 保留原匹配候选边界，归并完成后收缩用户段。allocate（347 行）按分配后的 held_effective 更新边界；不改变 active/held 分摊公式。无证据段不产生时长。
- Claude：保留 gap 分段，去掉消息锚点对边界的额外扩张（142 行）。ChatGPT：仍保留相同 URL 合段，但多次访问显示为分开的实际区间。computer：无输入的窗口观察不再扩张活动边界。Ear：原本已经用裁剪后的录音区间，无需修改适配器；仍然只是录音跨度估计。
- render（403 行）按实际区间交集选择「同时」和录音宿主，active 不足 3 分钟的段不能当宿主；保留原零碎合组和明确学到/产出的例外。517 行逐个显示实际区间，合组也不把间隙展示成连续活动。
- Codex 标题直接复用 focus 使用的 sources.codex 内已有首条用户消息前 160 字逻辑（sources.py:155），包括窗口前首条用户消息；完全无消息时为「未命名对话」。未修改 focus.py，focus 原来以 start=0 读取用户记录的行为保持一致。
- warn_spans（179 行）在 render 修正边界前检查跨度 > 2 小时且 > 实际区间并集 3 倍，写 stderr 和 JSON warnings。
- 文档更新 `pulse/README.md` §九及 §五相关展示说明。未新增模块或核心类型，沿用 segment / intervals / held 术语，没有引入重复概念。
