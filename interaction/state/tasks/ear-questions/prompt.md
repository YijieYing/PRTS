# 任务：根据旧 Ear 的转写起草基准问题（带证据索引）

工作目录：~/.ear-baselines/questions（输出写在这里）。只读材料：
- ~/.ear-baselines/inventory/index.json：433 段录音的索引（id、status、started_at（+08:00）、duration_s、counts、preview）。
- ~/.ear-baselines/inventory/transcripts/<id>.md：408 段录音的时间线（MOSS 转写带局部说话人标签、PANNs 环境声、GPS、手机状态；时刻都是 +08:00）。共约 8.6 MB，一次读不完，请写脚本检索、按日期和关键词抽样，再细读相关片段。

不要改 inventory 目录里的任何文件，不要访问网络，不要提交 git。

## 背景

我们要比较几种让 agent 理解一个人录音的方法（agent 直接读旧 Ear 的全量结果 vs 我们的新流水线）。需要一套问题：把问题交给 agent，看它回答得对不对。录音主人是一名学生/研究者，录音覆盖 2026-07-14～11-05，约 163 小时。这份题是草稿，录音主人会逐题听录音核对答案。

## 要什么

起草 **26 道题**（负责人要 20 道，多 6 道备用），覆盖这些类型，每类至少 3 道：

1. **固定习惯**：反复出现的规律。例如：近期是不是在上某门课、通常星期几几点上、上的是什么课；通常在哪几个地点工作或学习（用 GPS 坐标聚类，给出坐标和对应录音，不用知道地名）；吃饭、通勤等规律。答案必须由 ≥3 段不同日期的录音支持。
2. **具体事件的内容**：某次会议、课、谈话里讨论或决定了什么，例如「在某次关于 X 的会上提到了哪些事」「某天下午讨论的项目下一步要做什么」。
3. **具体小事实**：某个数字、名字、地点、物品、约定的时间等，只在一两段录音里出现。
4. **时间定位**：某件事发生在哪天、几点（例如「第一次提到 X 是什么时候」「最近一次 X 是哪天」）。
5. **跨录音汇总或推断**：需要把多段录音合起来才能回答（例如「九月中旬那几天主要在忙什么」「X 项目从开始到最近的进展」）。
6. **无法回答**：2～3 道看起来合理、但录音里其实没有依据的题（用来测 agent 会不会编造）。写明你检查过哪些关键词或日期，确认没有依据。

约束：
- **不出依赖「哪句话是谁说的」的题**：说话人标签只在 30 分钟块内有效，agent 目前做不到人物归属。问「会上提到/讨论了什么」，不问「我说了什么」「某人说了什么」。
- 答案必须来自录音内容（转写、环境声、位置），不能只靠录音的日期和时长就答出来。
- 题目分布在不同月份和日期，不要集中在一两天；避免需要隐私细节才能答的题（不涉及病情、财务、他人私事）。
- 题目用自然的中文问，像录音主人会问自己的助手那样；题目里不要透露答案线索，不要提「转写」「块」「S01」等内部术语。
- 转写有错别字和识别错误（例如嘈杂环境、外语）。答案要基于你能交叉印证的内容；拿不准的地方在「核对提示」里写清楚。
