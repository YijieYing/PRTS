# E2 阶段 A：离线重放的结果（2026-10-21）

> 一句话：**在真实的 agent 工作轨迹上，现实中的压缩策略比理论最优多出 5–8 倍的缺页；而且有一半的“重读”发生在 2.4 万 token 之后，常见的窗口根本装不下。**但阶段 A 只能统计“重新读文件”这种显式缺页，看不到“记住用户约束”的价值，这正是阶段 B 要回答的。

详细报告：[results/phaseA/REPORT.md](../../../research/PRTS/results/phaseA/REPORT.md)（代码提交 74d2a14，30 项测试通过，全程离线）。

## 数据
- 本机全部 Codex thread（141/141，含 102 个 zstd 压缩的旧记录）和 7 个 Claude session。
- 约 2,340 万 token，6.7 万次引用，其中文件读取 8,548 次，分布在 2,817 个文件上。
- 有 23.5% 的工具调用无法静态解析（主要是 Python heredoc 和动态脚本），已经逐类列出。

## 主要发现
**1. 现实策略和理论最优差得很远。**以 16k 窗口为例，下面是显式缺页数：

| 策略 | 缺页 | 说明 |
|---|---:|---|
| OPT（知道未来，理论下界） | 112 | |
| LARGEST（先逐出最大的页） | 701 | 现实策略里最好 |
| LRU | 806 | |
| FIFO | 832 | |
| 类 Claude Code | 969 | 摘要按“什么都没留住”计，是上界 |
| 类 Codex | 1,153 | 同上 |
| TYPE（固定用户消息） | 1,323 | 最差 |

**2. “先逐出最大的页”最好，这说明大块的工具输出很少被再次用到。**Claude Code 优先清掉旧工具输出，方向是对的。

**3. 类 Codex 和 TYPE 吃亏，是度量本身的盲区。**这两种策略都把空间留给了用户消息。阶段 A 只统计“重新读文件”，**用户消息从来不会被“重读”**，所以留住它们的价值在这里完全看不出来，只体现为占用了空间。它们到底值不值，必须用阶段 B 的探针去测：用户说过的约束，压缩之后还记不记得。

**4. 重用距离很长。**同一个文件两次读取之间，中位数隔了约 2.4 万 token，P90 约 27 万 token。也就是说：
- 窗口在 32k 以下时，一半以上的重读必然缺页；
- 即使窗口有 20 万 token 量级，仍有 10% 以上的重读落在窗口外。

“把需要的内容按需取回来”（也就是 recall 机制）在真实工作里不是边缘情况。

**5. Belady 式反常确实出现了，但很少，而且原因不同。**FIFO 和 LRU 各有 2 个 session，窗口变大后缺页反而变多。不过这些都是因为**页的大小不一样**：窗口扩大之后开始能装下大页，大页又挤掉了别的页。这不是经典定理里那种等大小页的反常。所以“LRU 不会出现 Belady 反常”的结论，在 agent 上下文里并不成立。

## 局限（为什么还不能下最终结论）
- 引用串是固定的：真实情况下，模型看到什么会影响它下一步读什么。
- 摘要类策略按上界计算。
- token 数用 bytes/4 近似。
- 多条命令拼在一起的输出，只能按命令平均分摊大小。

## 下一步：阶段 B
从 293 个候选切点中挑选。优先选择：读取范围相同、中间没有写入、间隔很长、并且不同策略在这里“意见不一”的位置；再补上一些早期的用户约束。只用 PRTS 和 LearnCodex 的 session，人工审查之后，先跑 B0 和 B1 两道基线筛选，再跑 160 次调用的试点。key 已经就绪。
